# 系统回收像素界面（1.3.10）

玩家使用 `/market recycle`，或首页「系统回收」。点击背包中的标准物品，默认选中背包存储区同种、同元数据物品的全部数量。装备栏和副手不参与。特殊元数据物品仍不能冒充标准资源回收。

数量条呈连续绿色轨道和滑块外观，点击七个槽位选择比例，最后一档全部。原版箱子不提供鼠标像素坐标，因此这是七档点击选择，不是连续可拖动控件；没有 +1 / -1 按钮。返回与确认只位于上部容器区域。

皮肤使用实际 176×126 PNG，不把高清概念图缩小投入运行。玩家背包维持原版。物品名称由物品悬浮提示显示；数量、可用总量、固定单价与预计收益通过专用数字 Glyph 展示。回收免税、不产生市场库存。

## 安装与资源包

- JAR：`target/v1.3.10/StarMarket-1.3.10.jar`。
- CE 资源：`server-assets/CraftEngine/resources/starmarket-recycle/`，放到对应的 `plugins/CraftEngine/resources/starmarket-recycle/`。
- 皮肤配置：`server-assets/StarMarket/gui/recycle.yml`，先备份，再替换服务器对应菜单。
- 普通 JAR 默认仍提供不依赖 CE 的箱子菜单；已有 schema 1 菜单自动备份迁移，保留未改动字段及原文案，并修正整叠描述。
- 正常重启加载新 JAR 后，执行 `/ce reload` 加载新增资源，再执行 `/ce workflow default` 生成、验证、上传及发送现有整服资源包。生产服当前 default 工作流含这些步骤；其他服以自己的工作流为准。
- 客户端须接受新资源包。不要用本次隔离测试生成的小资源包替换整服资源包。

数量数字更新使用已验证存在的 Bukkit `InventoryView.setTitle`，保留服务端容器与会话，不调用关闭/重开菜单。底层会发送窗口标题刷新包；客户端视觉是否闪烁仍需实际进服验收。

## 1.3.11：预览图标本身居中

菜单预览支持 `elements.I.item-models.<MATERIAL>` 按材质选择专用资源包模型；空状态使用 `empty.item-model`。目前提供箱子、圆石、橡木原木、铁锭的模型，GUI朝向/比例从本机匹配26.2客户端JAR实际模型继承，仅上移8逻辑像素，使图标中心从y44到信息区中心y36。真实物品和普通背包模型不变。新增回收品类时需增加对应预览模型及映射，否则保留原版显示。

本次构建63项单元测试通过，26.2/26.3各34项运行断言通过（包括预览模型选择、真实物品元数据不改变）；CE26.9.2构建与资源检查通过。新JAR已暂存本地/云端update，新模型与对应菜单字段已备份同步；需要正常重启和CE资源包重新生成发送。客户端最终位置待验收。
